# AnyKeep 4.0.5 — critical media-transfer hotfix

This stable patch release addresses a critical hang in XMPP/Jingle media
transfers. Version **4.0.4** was already used by a nightly build and is skipped
for this stable release.

## Fixes

- **SCTP/Jingle deadlock:** update to **Iris v1.6.2**. Application-level
  DataChannel callbacks are deferred out of the usrsctp receive stack so
  incoming packets cannot recursively re-enter its locked processing path.
- **Encrypted media serving:** initialize the local media store asynchronously
  when a remote party requests a Jingle range, so initial QtKeychain access does
  not enter a nested event loop from an SCTP callback.
- **Media downloads:** allow up to three active Jingle range transfers instead
  of globally serializing all pending requests. Multi-range transfer within a
  single shared SCTP association remains separate follow-up work.

## Validation and upgrade notes

The original hang was reproduced on Gentoo; after the fix, video playback and
multiple seeks succeeded without freezing. The patched Iris v1.6.2 release and
the AnyKeep integration passed their cross-platform CI suites.

Existing encrypted note and media formats are unchanged. As a precaution,
back up important notes before upgrading and allow synchronization to finish.

The broader removal of synchronous keychain APIs is tracked separately:
https://github.com/Ri0n/AnyKeep/issues/191.

This release is complete only when the Windows, macOS, Linux and Android
package jobs succeed and GitHub release assets are published.
